# KaraPoke（カラポケ）

Spotifyの再生履歴から歌いたい曲を見つけて、カラオケ用のセットリストを作るWebアプリです。

技育CAMPハッカソン Vol.13 で努力賞をいただきました（チーム名：マサイ族）。初めてのハッカソン参加でしたが、チームで技術的な壁を乗り越えて受賞できました。

## 作ったきっかけ
カラオケに行くと「次、何を歌おう？」と迷って、履歴を探しているうちに時間が過ぎてしまうことがよくありました。選曲で迷う時間をなくして歌う時間を増やしたいと思い、普段聴いている曲からすぐにセットリストを作れるアプリを作りました。

## できること
- Spotifyでログインすると、最近聴いた曲・お気に入りの曲・おすすめ曲が表示されます。
- 気になった曲を「リストに追加」でストックして、カラオケで入れる曲のリストを作れます。
- 歌った曲ごとに点数と感想を残せるので、次のカラオケの参考にできます。

## 使用技術
- フロントエンド：JavaScript / React（Vite）/ CSS
- バックエンド：Python 3 / Flask / Spotipy / Flask-CORS
- 認証：Spotify OAuth 2.0（Authorization Code Flow）

## チーム
4人で開発しました。フロントエンド2人（私を含む）、バックエンド2人です。

## 担当したこと
私はシステム全体のつなぎ込み、フロントエンドの設計、Gitの運用管理を担当しました。メンバー全員がチーム開発は初めてだったので、実装だけでなく、開発が破綻しないためのルール作りも引き受けました。

### Gitの運用ルール作り
バージョン管理も初めてだったので、調べながら次のルールを決めて、チームで守るようにしました。

- `main` ブランチに直接マージしない
- ブランチは機能ごとに切り、`feature/機能名` のように命名する
- コンフリクトを防ぐため、作業範囲をコンポーネント単位で分け、同じファイルを複数人で同時に触らない

最初はルールがなかったのでコンフリクトが何度も起きました。この経験から、ブランチを細かく分けることと、こまめにコミットすることの大切さを学びました。

### フロントエンドの設計
開発スピードと保守性を両立するため、Reactのコンポーネントごとにファイルを分けました。誰がどのファイルを担当するかがはっきりして、作業分担もしやすくなりました。

### フロントエンドとバックエンドの連携
ReactとFlaskの間の通信を実装しました。JSONレスポンスの形式や通信の流れを整理して、フロントとバックエンドをつなぎ込むところまでを担当しました。

## 苦労したこと

### 開発スピードと技術理解の両立
バックエンドのFlaskはチーム全員が未経験でした。48時間で完成させることを優先して、基礎部分の実装にはAIを使いました。そのおかげで、未経験の技術でもスピード感を持って形にできました。

一方で、AIが生成したコードに頼りすぎて、内部の仕組みを自分で理解しきれていない部分が残りました。動くものを作るだけでなく、使った技術を自分のものにすることが大切だと痛感しています。これからはAIを、自分の理解を深めるための補助として使えるようになりたいです。

### データは届いているのに表示されないバグ
ブラウザの検証ツールとサーバーログを突き合わせて、データの型（配列かオブジェクトか）や非同期通信が終わるタイミングを確認しました。その結果、Reactのstate更新とAPIレスポンスが噛み合っていないことが分かり、コードを直して解決しました。

### カラオケボックスのようなUI
アプリ全体をダークモードとネオンカラーで統一しました。開いた瞬間にテンションが上がるような雰囲気を目指しています。

## 振り返りと今後
- コードを書く前にGitの運用ルール（コミットの粒度やブランチの切り方）をしっかり決めておくことが、開発後半の進みやすさを左右すると感じました。
- 今後はプルリクエストでのコードレビューを取り入れて、メンテナンスしやすいリポジトリ管理を心がけます。
- APIのレート制限への対応など、エラーハンドリングも強化したいです。
- このサービスはモバイルアプリにするともっと活きると思っています。バックエンドでAIに頼りすぎた反省とGit運用の反省を活かして、開発を続けていきます。
